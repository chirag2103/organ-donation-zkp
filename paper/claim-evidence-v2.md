# Revised claim-to-evidence map

The normative behavior is [PROTOCOL_V2.md](../docs/PROTOCOL_V2.md). This map applies to the revised local synthetic implementation, not the historical prototype or a production deployment.

| Paper claim / research question | Implementation | Evidence and interpretation |
|---|---|---|
| RQ1: only approved membership authorizes the specified role | `circuits/roleProof.circom`, `contracts/{RoleRegistry,PFEKeyIssuer,ZKPVerifier}.sol`, `server/auth.js` | `test/v2/proof.test.js`, `contracts.test.js`, `api.test.js`; real proofs and injected HTTP failure cases are distinguished. Two approved members share one root. |
| Wallet, chain, issuer and root-version binding; nullifier replay rejection | Circuit public signals and `PFEKeyIssuer.sol` checks | Real proof mutation and sender tests; expiry/revocation/root-update contract tests. Root update requires all affected members to authenticate again. |
| Credential secret stays in the browser during authentication | `src/App.jsx`, `src/prover.worker.js`; public membership endpoint | Live browser request-body assertions in `browser-acceptance.json`. The service still sees clinical inputs during registration. This does not protect against a malicious browser application origin. |
| RQ2: measured authorization and matching overhead | `scripts/benchmarkV2.js`, isolated `contracts/benchmark/WalletRBAC.sol` | Completed `evaluation-v2/benchmark-v2.json`, raw samples and metadata. Repeated timing metrics use ten warmups and thirty measured samples; cold issuance gas is recorded separately from warmed updates. Node proving is not browser timing. |
| RQ3: exact fixed-policy BFV computation | `server/bfvService.js`, independent reference in `shared/protocol.mjs` | `test/v2/bfv.test.js`: all ABO pairs and urgency classes, every mismatch boundary, seeded random inputs and positive noise budgets. Experimental binary features and weights have no clinical validation. |
| No plaintext clinical fields on the revised chain | `contracts/OrganRegistry.sol`, `server/service.js` | Contract ABI/storage-shape regression and API stored-record regression. Transactions still expose wallets, opaque IDs, entity types, anchors and timestamps. |
| Canonical restricted computation and owner-bound jobs | `server/app.js`, `server/service.js` | `test/v2/api.test.js`: removed unsafe routes, permission checks, invalid fields, result ownership, activity rechecks, bounded batches and job-local encrypted cache. |
| RQ4: records survive service restart and missing keys fail closed | `server/bfvService.js`, `server/index.js`, SQLite store | BFV restart/wrong-key tests and live demonstration, including startup with an empty database against a nonempty chain. Operator wrapping secret and database backups remain necessary. |
| RQ4: revocation replays missed events and exposes retryable failure | `contracts/LifecycleManager.sol`, `server/revocation.js` | `test/v2/recovery.test.js` plus live donor and offline-recipient revocation. Fault-injection tests cover failed GC, confirmation depth and processed-history changes. |
| Local cleanup, not universal erasure | Canonical key deletion, Kubo unpin/GC, durable cleanup status | `recovery.test.js` and live Kubo cleanup. External replicas, backups, copied keys and prior outputs cannot be recalled. No GDPR compliance determination is claimed. |
| End-to-end application works on the tested revision | `scripts/demo.js`, `scripts/verifyV2.js` | `evaluation-v2/validation.json`: 28 passing tests, zero skipped in the explicitly enabled live run; `browser-acceptance.json`: 11 live checks. Default tests explicitly skip live infrastructure. |

Fresh local deployment, synthetic fixtures and an EIP-1193 test-wallet adapter are used. MetaMask extension interaction, public-network finality, clinical outcomes, independent multiparty setup and multi-hospital governance are not established by these results. Source and artifact hashes identify the evaluated working tree; the parent commit alone does not identify the uncommitted revision.
